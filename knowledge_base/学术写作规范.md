# 学术写作规范

适用范围：本规范主要面向 IEEE 期刊论文，尤其是无线通信及相关方向。撰写其他领域或体裁的论文时，请结合学科惯例和目标期刊要求甄别使用。


## 第一类：通用写作准则

### 1.1 **准确对应对象与机制。**
技术对象的功能、影响因素和适用条件应逐一对应，避免把一种方法的局限归于另一种方法。区分直接作用与间接收益，必要时补充中间机制，使因果关系完整。

例：不要直接写“宽带信号提供精细指纹”，可写“更大带宽提高时延分辨率，有助于提取更精细的信道指纹”。

### 1.2 **使主张与证据相称。**
对贡献、性能、泛化能力和适用范围的表述，应与实际结果、比较对象及前提条件一致。局部改善不能写成全面优越，有限场景的验证也不能直接推广到未经测试的条件；同时应清楚说明已有证据支持的价值。

例：若性能增益主要出现在低信噪比条件下，应写“在低信噪比下优势明显”，而非笼统地写“显著优于现有方法”。

### 1.3 **让句子/段落环环相扣。**

尽量让句子的前半部分承接上一句后半部分的概念或相关信息，再由后半部分引出新内容，形成“已知信息—新信息”的推进。段落之间应承接前文留下的问题或结论。衔接可通过前一句/尾的新感念/信息相关词语的重复使用来实现，也可靠语义关系衔接来实现。

例1：本文提出一种跨场景预测方法。该方法使用相对位置特征。这些特征减少了模型对绝对坐标的依赖。
例2：xx is essential for scalable CKM deployment, since xx. An initial attempt is [R], which xx. Nevertheless, [R] still relies on xx.

### 1.4 **控制单句信息量。**
每句话围绕一个核心意思展开，避免同时塞入技术优势、方法局限和研究动机等不同层次的内容。涉及多个对象及多个原因时，应明确各自的对应关系，必要时拆句或删减次要信息。

例：原句“Conventional time-of-arrival (ToA), angle-of-arrival (AoA), or multibase-station methods are constrained by synchronization requirements, line-of-sight (LoS) availability, or hardware overhead.”

分析：句子本身通顺，但同时列出三类方法与三项限制，读者难以判断哪些限制对应哪些方法。应按实际关系分别说明，或只保留与研究动机最相关的限制；不能仅凭排列顺序将两组内容一一配对。

### 1.5 **统一术语与缩写。**
同一概念使用同一术语，避免为追求措辞变化而交替使用近义名称；含义相近但不等同的概念应明确区分，不能混用。缩写首次出现时给出全称及缩写，后续保持一致，避免同一对象出现多套名称或缩写。

例：若已用“steering vector”表示导向矢量，后文就不要无说明地改称“array response”或“spatial response”。

### 1.6 **删除冗余表达。**
删除重复传达同一信息的词语、限定和句子，但保留影响结论成立的条件。可尝试删去某个成分，检查原意、指代和逻辑是否仍然清楚，避免只为缩短句子而损失必要信息。

例：若“根据式（8）的观测模型”已明确依据，就不必再加含义相同的“在上述给定条件下”。

## 第二类：摘要和引言的写作准则

适用范围：本类准则主要针对 IEEE Wireless Communications Letters（WCL）短文。用于 magazine 或其他 journal 稿件时，应结合目标期刊和文章体裁调整，不直接套用其中的章节组织与篇幅建议。

### 2.1 **理顺引言结构。**

按“大背景(big picture)—结构化文献综述—未解决的问题—本文工作与贡献”推进，可用以下三段/四段式组织；段数可随篇幅调整，但各部分的逻辑职责应清楚。

第一段讲大背景。从具体无线场景或基础问题切入，说明该问题影响哪些系统功能，以及在 6G 演进的哪些具体新条件下变得更难。避免空泛口号，用实际影响说明重要性，而不是只宣称问题“关键”或“重要”。

第二段讲小背景与文献综述。沿一条清楚的分类轴组织已有工作，例如可用的辅助信息、建模方式、方法论延伸，不要逐篇平铺罗列。
注意：分类逻辑尚未理清时，可先让 AI 辅助梳理框架，再由作者核查；若分类依据或各类工作的关系仍不清楚，应暂停内容生成，向作者指出具体逻辑问题，待作者梳理确认后再继续。

第三段总结局限并指出缺口。用有实际逻辑含义的过渡承接文献综述，概括已有工作的共性局限，或指出尚未解决的问题及被忽略的关键因素，解释为什么仍需要研究。连接词应表达转折、因果或递进关系，不能只作装饰。此段只讲“尚未解决什么、为什么重要”，将本文的研究目的、框架和组件留到下一段；篇幅较短时，可与第二段合并。

第四段介绍本文工作与贡献。用一小段连续文字交代研究问题、所提方法及创新、仿真发现，不建议采用逐项打点的形式，也不展开算法细节。

方法假设和详细适用条件放在 System Model 或 Problem Formulation 中明确说明，不在引言中展开；引言中的贡献表述仍须与实际适用范围一致。

例：现有方法仍需新场景测量 → 这使跨场景部署依赖现场数据采集，未解决的问题是如何减少这种依赖 → 下一段再介绍本文的预测框架与方法。

### 2.2 **准确呈现研究背景。**
结合真实的技术发展背景说明问题的重要性，区分技术已有的能力与当前受到关注的需求。表述既不应夸大，也不应因措辞过弱而掩盖研究价值；重要性应由具体需求支撑。

例：介绍无线定位时，可从通感一体化对环境感知的需求切入，而不笼统地称其为通信系统的“原生能力”，也不能称其为MIMO-OFDM系统的必要能力，因为MIMO-FDM系统在4G中已经实现了属于传统技术的无线定位功能。

## 第三类：系统模型和算法章节的写作准则

适用范围：本类准则针对 IEEE Wireless Communications Letters（WCL）短文，部分准则可通用（例如符号体系、符号定义、运算规范）。用于 magazine 或其他 journal 稿件时，应结合目标期刊和文章体裁调整。

### 3.1 **让系统模型准确、无冗余。**
System Model 应讲清系统设定、基本假设、输入输出、优化或估计目标，只引入后文真正使用的变量与记号。对采用已有模型且建模并非主要贡献的论文，可将半页到一页作为篇幅参考，避免写成教程；若新的建模思路本身就是贡献，可适当扩展。读者已能理解研究对象和目标后，就不必继续堆叠背景与符号。

例：采用已有 MIMO-OFDM 模型时，交代观测方程、信道假设和估计目标即可，不必重新讲解完整的 OFDM 原理。

### 3.2 **精简符号体系。**
仅定义后文实际使用且有助于表达的符号，避免为未使用的中间量或集合额外命名。引入新符号前，应检查现有符号能否直接表达；保留能简化重复公式的定义，删去只增加记忆负担的定义。

例：若算法始终逐路径使用导向矢量 $\mathbf{a}_l$，且从未进行整体矩阵运算，就不必额外定义 $\mathbf{A}=[\mathbf{a}_1,\ldots,\mathbf{a}_L]$。

### 3.3 **让符号直观易记。**
优先遵循领域常见约定，使数量、索引和物理对象容易对应，避免为求新颖而另造命名。大写字母可表示数量，相应小写字母表示索引；用户数、子载波数和天线数的字母选择可随领域惯例调整，但选定后应保持一致。矩阵及其元素尽量采用对应字母，收发端等角色使用直观标记。控制上、下标承载的信息层数，不必为每一层含义都叠加标记；确需同时区分元素与链路方向时，可将索引放在下标、方向放在括号上标，词语缩写使用正体。

例：用户数与索引记为 $K$、$k$，收发天线数记为 $M_{\mathrm{t}}$、$M_{\mathrm{r}}$；上行信道矩阵 $\mathbf{H}^{(\mathrm{UL})}$ 的元素记为 $h_{i,j}^{(\mathrm{UL})}$，下行对应使用 $\mathrm{DL}$。

### 3.4 **就近定义符号。**
符号应在首次使用处或相关公式附近解释，避免定义与使用相距过远。系统共有的基础符号应在系统模型等前置章节交代，算法特有的量则在需要时引入，不必为集中定义而无谓提前。

例：天线数 $K$ 应在介绍阵列模型时定义；算法的迭代次数 $t$ 可在介绍迭代步骤时再定义。

### 3.5 **规范数学字体。**
小写粗体表示向量，大写粗体表示矩阵，大写花体可用于表示张量；应在文中明确字体约定，避免与集合等对象的记号混淆。表示词语或缩写的上、下标使用正体，表示变量或编号索引的上、下标保留斜体；混合标记应按各部分的含义分别处理。字体的判断依据是符号的实际含义，而非字母数量，所有字体约定均应在行内公式与独立公式中保持一致。

例：向量、矩阵和张量可分别记为 $\mathbf{h}$、$\mathbf{H}$ 和 $\mathcal{H}$；$S_{\mathrm{src}}$ 中的 $\mathrm{src}$ 表示 source，用正体；$\mathbf{p}_{i,\mathrm{Tx}}$ 中的 $i$ 是索引，保留斜体，$\mathrm{Tx}$ 用正体。

### 3.6 **解释数学运算。**
首次使用专门的运算符或自定义运算时，应在公式附近说明其含义，必要时交代作用对象和运算方式。避免让读者依靠猜测区分不同运算，也不必在后文反复解释已明确的符号。

例：首次使用 $\mathbf{a}\otimes\mathbf{b}$ 时，说明“$\otimes$ 表示 Kronecker 积”。

### 3.7 **按问题、方法与整体算法组织方法章节。**
方法通常是全文核心，应通过若干小节展开，而非将建模、公式和实现混在一起。可先写问题表述（也可单独成节），再按模块或关键步骤介绍主体方法，最后汇总整体算法，按需要给出伪代码、运行流程、停止或收敛准则、复杂度及实现代价。流程型方法按“输入—处理—输出”组织，多模块方法按数据流或依赖关系组织；每部分先解释设计直觉及其如何解决问题，再给出公式和实现细节。

例：先说明“为何先抑制噪声再估计信道”，再介绍两步的计算，最后用伪代码串起输入、更新步骤和停止条件。

### 3.8 **补全逻辑与推导。**
检查句间及公式间是否缺少关键前提、变量替换或推导步骤，使读者能够沿着文字复现主要思路。常规计算可以适当省略，但决定结论成立的假设及关键等式不能省去。

例：将求和式中的交叉项消去时，应说明使用了“不同分量互不相关”等条件，而不只写“经简化可得”。

## 第四类：仿真章节的写作准则

### 4.1 **用仿真对比与分析支撑方法价值。**
仿真与讨论应围绕方法的核心主张组织证据，而非只汇报数值。横向比较应选择相关基线，评估性能、复杂度或鲁棒性；纵向分析可比较模块、参数和运行条件，解释方法何时有效、哪些设计发挥作用。新方向缺少标准基线时，可加强消融和敏感性分析，但不能因此省略可行的相关对比。分析应指出增益在哪些条件下更明显、可能原因及其系统含义，并区分已有证据与机制推测。

例：除与基线比较估计误差外，再移除去噪模块，考察误差随信噪比的变化，以判断该模块的作用是否主要出现在低信噪比条件下。

### 4.2 **按“图表内容—数值分析—解释或归纳”描述仿真结果。**
仿真参数、场景设置和对比方法应在仿真结果章节开头统一介绍。
分析各图表时不再重复基线方法或已有设置，先用一句话客观说明图表展示的内容，再用几句话提取有代表性的数值、变化趋势及差异，将所提方法与相应基线进行定量比较，避免逐项复述全部数据，也不要用“高、低、好、差”等模糊评价代替具体结果。最后用一句话说明结果表明了什么；若存在值得解释的现象，应说明原因，原因分析也可替代总结句。结尾不必用多句话反复强调方法优势。

例（数值仅作写作示意）：表 II 比较了两种方法在三个目标场景中的预测误差。所提方法的平均误差为 0.16，基线为 0.22，相对降低约 27%。其中，办公室场景的误差由 0.26 降至 0.18，会议室场景则由 0.19 降至 0.13。这些结果表明，所提方法在所测试的目标场景中降低了预测误差。
