# Digital-Mentor：写作与评审双技能

这个仓库设计的初衷，是以前老师会把论文改得满页红笔，很多问题会被一遍遍指出。随着课题组规模的扩大，现在这类高密度、一针见血的写作反馈越来越稀缺。为了让大家在AI时代能自主检查论文，决定把可复用的部分沉淀成可以调用、维护和迭代的技能。

大家可以把它理解为一种“导师经验的可移植封装”。它并不试图替代人的判断，也不承诺生成一份放之四海而皆准的神奇 prompt。它做的事情更朴素：把无线通信论文写作中的结构要求、术语约束、句法偏好和常见错误单独存起来，让 AI 在写作时先读这些，再动笔。

用袁老师的话说：“学术写作，80%都是八股文。” 相信大家写了几篇期刊论文后，也会深有同感。论文写作里确实有一部分是重复劳动。结构怎么搭，Introduction 怎样铺垫，系统模型该写到什么程度，首次出现的缩写怎么处理，图正文和 caption 怎样分工，哪些词一看就有 AI 腔。这些内容并不需要每次都从零开始发明。把它们做成技能的价值，不是为了偷懒，而是为了把注意力从重复召回转移到真正重要的判断上：问题是否成立，贡献是否清楚，证据是否充分，表达是否真的更好了。

此外，在与 AI 协作写论文时，作者也可能尚未想清楚某处该怎样改，或未能准确传达自己的想法。多轮修改后，这些问题会留在稿件里，甚至被顺畅的文字遮住。为此，本次更新在写作技能之外加入独立的评审技能：一个帮助作者写清楚，另一个从评审视角重新检查。

## 两个技能怎么选

| 技能 | 适合什么时候用 | 它主要做什么 |
|---|---|---|
| [`ieee_writer`](ieee_writer/SKILL.md) | 已有研究内容和基本思路，想起草、组织或修改文字 | 检查作者想表达的逻辑，再依据写作知识库完成结构化写作和局部修改。 |
| [`ieee_reviewer`](ieee_reviewer/SKILL.md) | 想跳出当前写作思路，重新检查论文 | 从相对独立的评审视角，按大修或小修模式找出有依据、可定位的问题。 |

`ieee_writer` 也会检查正在写的片段，但重点是帮作者把已有思想说清楚。需要一次独立的论文评审时，使用 `ieee_reviewer`；其模式在下文单独介绍。

## 下载与目录

下载整个仓库后，会得到下面的文件。若手动安装到 Codex，可将 `ieee_writer` 和 `ieee_reviewer` 两个文件夹分别放入本机的 Skills 目录；两个技能都要连同各自的知识库或参考文件一起保留。

```text

├── LICENSE
├── ieee_writer/
│   ├── SKILL.md
│   └── knowledge_base/
│       ├── 学术写作规范.md
│       ├── style_profile.md

    └── references/

```

此前从本仓库安装单个 `mentor-guidance-writer` 的读者，更新后请按新目录安装，并把调用名称改为 `ieee_writer`。原有根目录下的写作技能与知识库会迁入 `ieee_writer/`；评审技能放在 `ieee_reviewer/`。仓库保留既有 Git 历史，`LICENSE` 仍适用于开源内容。

## 使用 ieee_writer

写作之前，先告诉它目标期刊、要处理的范围、想传达的思路，以及相关结果和参考材料。已有草稿能够表达这些内容时，不必另写提纲。技能会判断论证是否连贯、结论是否有依据；关键思路还不清楚时，它会指出疑点，等作者厘清后再推进相关写作。

写作知识库分为四份文件，各管一件事：

| 文件 | 主要用途 |
|---|---|
| [学术写作规范.md](ieee_writer/knowledge_base/学术写作规范.md) | 提供写作准则，包括技术对象与机制、主张与证据、章节组织、符号和仿真分析等“八股”结构。 |
| [style_profile.md](ieee_writer/knowledge_base/style_profile.md) | 保存作者偏好的语气、措辞和行文方式，避免“AI味”。 |
| [memory.md](ieee_writer/knowledge_base/memory.md) | 保存研究方向的术语定义、缩写规则、短语参考，让措辞更加专业。 |
| [error_log.md](ieee_writer/knowledge_base/error_log.md) | 供作者查阅的历史错误案例，提升自己的审美与判断力。 |
### 三种常见写作模式
#### 1. 从零开始写

提供研究问题、想让读者理解的主张、论证顺序、已有结果和目标期刊。AI 先检查思路与证据是否对应，再参考知识库起草。若作者还在斟酌章节结构，可以要求先给写作方案。

```text
/ieee_writer
目标期刊是 IEEE Wireless Communications Letters。
我的方法章节思路是：先说明低信噪比下的估计困难，再解释为什么先去噪、后估计，最后介绍算法的输入、步骤与输出。
具体机制和实验结果见附件。请先检查这条逻辑；有疑问先指出，合适后再起草，不要自行补充技术动机或结论。
```

#### 2. 修改已有段落

提供原文、修改目标和必须保留的内容。可以只要求理顺两段之间的衔接、统一术语，或精简一段系统模型说明。AI 应围绕指定范围修改，并保留公式、假设和结论的原意。

```text
/ieee_writer
目标期刊是 IEEE Wireless Communications Letters。
这两段想先交代观测模型，再说明已知量与待估计量，最后明确估计目标。
请检查原文是否体现了这条逻辑；若有关键缺口，先指出。逻辑清楚的部分可以直接修改，但不要改变公式和技术假设。
```

#### 3. 检查指定章节或问题

写作过程中，也可以让 writer 核对某个片段是否把作者的想法讲清楚，例如引言的动机是否支撑所述问题、图表解释是否与结果一致。这是服务于局部写作的检查；完整的大修或小修评审由 `ieee_reviewer` 执行。只想听意见时，明确说暂不修改文件。

```text
/ieee_writer
目标期刊是 IEEE Wireless Communications Letters。
我的引言思路是：新场景测量增加部署成本，因此研究如何减少对现场测量的依赖；贡献范围以现有实验为限。
请检查草稿是否支持这条论证，指出具体位置、问题和修改建议。暂时不要修改文件。
```

## 使用 ieee_reviewer

请提供目标期刊、论文阶段、稿件材料，并选择 `--major`、`--minor` 或 `--both`。如果没有选模式，技能会先询问。`--major` 可阅读 PDF，但 LaTeX 源文件更便于核对；`--minor` 和 `--both` 需要 LaTeX 源文件，才能给出可操作的行级修改位置。

| 模式 | 重点检查什么 | 会生成什么 |
|---|---|---|
| `--major` | 12 个维度的大问题：贡献边界、理论推导链条、方法假设、主张与证据、仿真是否充分，以及论文是否符合目标期刊。 | `review_major.md`：问题、依据和修订方向。 |
| `--minor` | 按稿件顺序逐位置检查 14 类细节，如语法、措辞、数学记号、交叉引用、图表说明和图文一致性。 | `review_minor.md`：可定位的修改清单；作者可选择要执行的类别。 |
| `--both` | 先 major，再检查仍需保留的文字；不在即将重写的段落上反复校对。 | 两份评审文件和简短衔接说明。 |

两个模式都先产出 Markdown 评审结果或修改计划，作者确认后再改论文正文。例如：

```text
/ieee_reviewer --major
目标期刊是 IEEE Transactions on Wireless Communications。
请检查论文贡献、推导逻辑与仿真证据，先给出有原文依据的评审意见，不修改稿件。
```

```text
/ieee_reviewer --minor
目标期刊是 IEEE Wireless Communications Letters。
LaTeX 源文件路径：<你的 main.tex 路径>。
请逐位置检查语言、符号、交叉引用和图文一致性，先生成可审核的修改清单。
```

AI reviewer 的“大修”或“拒稿”判断不等同于真实期刊决定。我曾让它审阅一篇已被 IEEE TWC 接收的论文，它仍判断为“大修”。请重点看每条意见是否指出了真实问题、是否有稿件证据、解决后能否提高论文质量；拿不准的难题可以与合作者或导师讨论。

## 两个技能怎样配合

作者可以先用 writer 写出或修改一个章节，再请 reviewer 从整体论证或细节一致性上检查。评审意见出来后，先判断哪些是硬伤、哪些只是可讨论的建议；确认修改范围后，再让 reviewer 执行获批的修订，或让 writer 根据作者确认的思路重写指定段落。评审工具不会替代作者对研究结论的判断。

## 适用范围

这个仓库主要面向无线通信、信号处理、信道建模与物理层算法论文。不同期刊的篇幅、证据要求和表达方式不同，请在请求中给出目标期刊。技能可以帮助发现写作和论证问题；数值、引文与理论结论的真伪仍要依据原始材料核查。

## 写在最后

Karpathy 分享过一个值得我们警醒的判断：“You can outsource your thinking, but you can't outsource your understanding.” 换句话说，如果 AI 帮你改完一段话，你已经无法判断它是更好了还是更差了，这是一个危险信号，说明我们自己的审美和理解没有跟上。在 AI 时代，我们可以不再亲自做每一道繁琐工序，但仍然要做最后那个能分辨好坏的人。

从这个角度看，README 的重要性并不低于 SKILL.md。SKILL.md 更像一个可发布、可复用、可继续修改的示例；README 真正想传达的，是如何逐渐形成你自己的判断标准。如果发现 AI 的某些修改你无法判断好坏，最好的办法往往不是继续堆 prompt，而是专门开一个新的session，围绕这一处问题反复追问，把它真正吃透理解透。
